# Config / Settings / Constants / Templates / Schemas — Migration Plan

Realizes [ADR-005](adr/005-config-settings-constants-templates-schemas-ssot.md).

**Tracking:** beads epic `mro-wkii` with phase children `mro-wkii.1` (P0) …
`mro-wkii.7` (P6). Per operator decision, **P6 governance alignment lands
before P1** (`mro-wkii.2` depends on `mro-wkii.7`).

This plan is **design-only** until approved. No code is changed by this
document. Each phase lands under its own bead with `make check` exit 0 +
`make test` green + atomic commit as the evidence gate. Net LOC must be
negative for every migration phase (constants shrink, config/data grows).

## Invariants (apply to every phase)

- **Runtime direction:** `flext-infra → flext-cli → flext-core`. flext-core
  never imports flext-cli/flext-infra at runtime (examples/scripts/tests only).
- **Config lives only under `config/`.** No schema, config source, or
  parametrization outside `config/` + sibling `schemas/`.
- **Config ≠ settings.** The settings-bound subset is a separate file
  (`config/settings.yaml`), never mixed with execution config.
- **No hardcoded large structures** in `_constants/`. Defaults only; big/derived
  structures are generated by a private `_constants` builder from `config/`.
- **Big strings are Jinja2 templates** under `templates/`, rendered through
  `flext-cli`.
- Every file operation, output, formatting, and schema/template routine flows
  through `flext-cli` (`u.Cli.*`).

## Directory convention (per package and for `~/.ai-hub`)

```
<pkg>/
  config/
    <domain>.yaml            # execution parametrization (agents, mcp, workspace, skills, …)
    settings.yaml            # ONLY the subset that flows into FlextSettings
  schemas/
    <domain>.schema.json     # one schema per config file, same base name
    <domain>.yaml            # execution parametrization (agents, mcp, workspace, skills, …)
    settings.yaml            # ONLY the subset that flows into FlextSettings


  src/<pkg>/
    _constants/*.py          # scalar defaults + invariants only
    _constants/_generated.py # dynamic builder: config → structures used by methods
    settings.py              # FlextSettings subclass (env override)
  templates/*.j2             # all large/generated string bodies
```

## Phase 1 — flext-core: minimal contracts, drop unused jinja2 — `mro-wkii.2`

Scope (core stays runtime-minimal, `c/t/p/m/u` only, stdlib only):

- Add base **contracts** consumed by all layers:
  - `p.Config*` protocol (load/merge/env-override/validate shapes),
  - `m.Config*` models (frozen Pydantic v2 config record + schema-ref),
  - `t.Config*` typing aliases.
- Add minimal runtime loader used by core itself: `u.config_*`
  (stdlib `tomllib` read + `string.Template` expansion + dict merge +
  env-override). **No Jinja2, no yaml/jsonschema in core.**
- Remove `jinja2` from `flext-core/pyproject.toml` dependencies (declared but
  unused in `src/`); verify with deptry + `make check`.
- **Evidence:** `make check`/`make test` green on flext-core; deptry clean.

## Phase 1.5 — flext-core: `FlextConfig` frozen singleton + dual accessor — `mro-wkii.9`

Realizes ADR-005 §7 (runtime objects). Foundation-first; TDD; single commit.

- **`FlextConfig` frozen sibling base** (`_config/_base_parts/…`): reuses the
  per-class `_instance`/`_lock`/`__init_subclass__` machinery copied from
  `FlextSettings`, but `model_config = SettingsConfigDict(frozen=True,
  extra="forbid")`, `fetch_global()` only (no `update_global`). Overrides
  `settings_customise_sources` → `TomlConfigSettingsSource` (stdlib) for its local
  `config/*`.
- **`FlextConfig` facade** (`config.py`): MRO-composed, flat fields per namespace
  (mirror `FlextSettings`); root alias `config`.
- **Dual accessor:** add `config: p.Config` field to `m.ServiceRuntime` beside
  `settings`; add a `config` lazy property to `FlextMixins` beside `settings`
  (`self._get_runtime().config`); populate it via `FlextConfig.fetch_global()`.
  `settings` and `config` stay independent — neither exposes the other.
- **Root + facade aliases:** `from flext_core import settings, config`; optional
  `u.settings()` / `u.config()` for non-service classes. Register both in the lazy
  export map (never eager) — preserves zero import-time coupling.
- **Do NOT** add `settings`/`config` to `EnforcedModel` (field-collision).
- **Evidence:** RED test (`config` on a service returns the frozen
  `FlextConfig` singleton; `settings` unchanged) → GREEN; `make check`/`make
  test` green; no new import cycle (import smoke on `c/t/p/m/u`).
- **Legacy removal (same cycle, ADR-005 §8):** delete `FlextSettings.apply_override`
  (DEPRECATED shim) and migrate its only users (`test_settings.py`,
  `ex_02_flext_settings.py`) to `update_global`. Net LOC negative; no orphan refs.

## Phase 1.6 — scaffold: base + `config.tpl` only, distribute config — `mro-wkii.10`

Minimal executable slice of ADR-005 §9 (the full hierarchical standardizer is
deferred to bead `mro-wkii.11`). Reuses the flext-infra scaffolder (single
owner); names resolved via `u.compose_namespace_config` + `u.read_project_constants`
(SSOT, never parallel detection).

- **flext-core reference first:** fix `from flext_core import config` (broken
  today) — add `config` to the lazy facade discovery + `config = FlextConfig`
  alias, `make gen`, verify `from flext_core import config` resolves.
- **New `RUNTIME_MODULES` tuple** (`flext-infra/_constants/codegen.py`), applied to
  the **package dir only** (never examples/scripts/tests):
  `("config.py", "Config", "FlextConfig", "Runtime config")`.
- **`config.tpl`:** emit `class FlextXConfig(FlextConfig)` + `config = FlextXConfig`
  alias + standardized `__all__`.
- **`config/` dir:** `_scaffold_project` creates `[project root]/config/` + a
  commented `config/config.yaml` when missing (`DIR_CONFIG` constant; new
  `.yaml`-writing branch — `_scaffold_dir` is `.py`-only).
- **Non-destructive:** existing `config.py`/`config/` respected; on incompatibility
  warn loudly + write `<module>.tpl.rej` (git-ignored) and continue; remove the
  `.rej` on later success.
- **Distribute:** run `flext_infra codegen scaffold --apply` across the 30
  projects; `make gen` regenerates lazy `__init__` so `from flext_x import config`
  resolves.
- **Evidence:** `from flext_core import config` works; a sample project has
  `config.py` + `config/config.yaml` and `from flext_ldap import config` resolves;
  `make check`/`make test` green on touched projects.

## Phase 2 — flext-cli: universal engine (amplifies core) — `mro-wkii.3`

flext-cli imports the core contracts and provides the workspace engine:

- `u.Cli.render_template(path|str, context) -> r[str]` and
  `render_template_to(path, dest, context) -> r[bool]` — Jinja2 with
  `render_template_to(path, dest, context) -> r[bool]` — Jinja2 with
  `StrictUndefined`, `FileSystemLoader`, autoescape select. Owns `templates/`
  resolution.
- `u.Cli.config_load(path, *, schema=None, env_prefix=None) -> r[m.Config]` —
  multi-format (YAML default, TOML, JSON via existing `yaml_*`/`toml_*`/`json_*`),
  env-override + merge, optional schema validation.
- `u.Cli.yaml_validate_schema(data, schema_path) -> r[bool]` — JSON Schema
  (add `jsonschema` to flext-cli deps; it is the correct owner).
- `u.Cli.config_load_dir(dir) -> r[Mapping[str, m.Config]]` — load every
  `config/*.yaml` with its `schemas/*.schema.json`.
- Keep these as generalist primitives (extendable), never per-project logic.
- **Evidence:** flext-cli `make check`/`make test` green; new primitives unit-tested.

## Phase 3 — flext-infra: enforcement rules (data-driven) — `mro-wkii.4`

Add rules to `flext-infra/_enforcement`, registered in `c.ENFORCEMENT_CATALOG`,
fail-closed via the pytest dispatcher:

- `no-large-literal-in-constants` — mapping/sequence literal over threshold in
  `**/_constants/*.py` (excluding `_generated.py`) → fail.
- `config-only-under-config-dir` — parametrization read outside `config/` → fail.
- `template-not-inlined` — multi-line string used as a template body instead of
  `templates/*.j2` → fail.
- `config-requires-schema` — a `config/*.yaml` without matching
  `schemas/*.schema.json` → fail.
- `config-settings-not-mixed` — settings-bound keys present in an execution
  config file → fail.
- Ship each rule **disabled → warn → error** staged, so migration can land
  package by package.
- **Evidence:** rules unit-tested against fixtures; catalog rows added.

## Phase 4 — `~/.ai-hub` reference migration — `mro-wkii.5`

The control plane is the reference implementation and migrates first end-to-end:

- Rename `config/aihub.toml` → `config/ai-hub.yaml`; split by domain into
  `config/agents.yaml`, `config/mcp.yaml`, `config/workspace.yaml`,
  `config/skills.yaml`, `config/hooks.yaml`, etc.
- Add `schemas/*.schema.json` per file (migrate the existing
  `~/.ai-hub/schema.json` + `config/models.json` into this convention).
- Extract the settings-bound subset into `config/settings.yaml`.
- Move large `_constants/mcp.py` structures (`MCP_ROUTING_CLIENT_SPECS`,
  `MCP_ROUTING_GENERATED_AGENT_FILES`, `SKIP_DIRS`, spawn tables) into
  `config/` data; regenerate them in `_constants/_generated.py` via the
  `flext-cli` loader; methods consume the generated structures.
- Move big string bodies (`templates/*.tmpl`, inlined bodies) to `templates/*.j2`.
- Point `AiHubConfig`/`settings.AiHub.config` at the new loader (`u.Cli.config_load_dir`).
- **Rewrite `~/.ai-hub/docs/adr/0008`** to describe the config-SSOT control plane
  (config/ dir + schemas + generated constants + Jinja2 templates), superseding
  the TOML-only registry framing.
- Update ai-hub docs + skills that reference `aihub.toml`.
- **Evidence:** ai-hub `make check`/`make test` green; all consumers of the old
  `aihub.toml` path migrated (grep-proof, no orphan references).

## Phase 5 — FLEXT packages (one bead each) — `mro-wkii.6`

For each package (start with `flext-core`, `flext-cli`, `flext-infra` self-hosting,
then platform, domain, integrations):

1. Create `config/` + sibling `schemas/` + `config/settings.yaml`.
2. Move execution parameters out of `_constants/` into `config/*.yaml`.
3. Replace large literals with `_constants/_generated.py` built from config.
4. Move any inlined template bodies to `templates/*.j2`.
5. Repoint `settings.py` at `u.Cli.config_load` for the settings-bound subset.
6. Delete the superseded literals/paths in the **same** change.
7. Flip that package's enforcement rules from warn → error.

- **Evidence per package:** `make check`/`make test` green; net LOC negative;
  enforcement error-level passing.
