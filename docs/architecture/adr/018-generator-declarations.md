# ADR-018 — Generator Declarations Law

## Offline dependency and architecture references (amended 2026-10-28)

**Accepted target; acquisition, publication and runtime acceptance are pending.**
The operator selected offline external content with reproducible refresh:
`upg` resolves official sources, versions, hashes, formats, licensing and attribution

consumer; FLEXT neither imports AI Hub/CRG nor implements another wiki renderer.

observed structure, and Beads owns intent, acceptance and execution evidence.
Confirmed CRG findings update the existing canonical issue when equivalent;

Wiki generation never creates or closes Beads by itself.

## Context

The lazy-init and `pyproject.toml` generators accumulated accommodations that decide
behavior from names and hand lists instead of declarations: a filename→letter table
(`NAMESPACE_LAYER_BY_FILE`, five readers), closed folder sets (`ROOT_WRAPPER_SEGMENTS`,
`NON_PUBLIC_LAZY_ROOTS`, `ALL_SCAN_PATTERNS`, `env-dirs`/`test-like-dirs`, a literal
fallback in `namespace_config`), a hardcoded `TEST_RUNTIME_ALIAS_TARGETS`, `ALIAS_NAMES`
used as the list of who exists, hand-declared `root_packages`/`root_modules`, a
single-part package name treated as a public root, an advisory-gate list by name, a
guard for one `services/models.py`, and an `examples/` bypass in the validator. Every
consumer of the generator inherited them. On 2026-09-20 the fleet `make gen` broke
(`flext-infra a43dcf547`) because export discovery accepted any class of a module with
no `__all__` and rendered `from .01_basic_usage import …`.

The operator negotiated the correct contract point by point and ordered it to become a
FLEXT rule generators cannot violate, followed by the extermination of every hack and of
the permission that tolerated it, one by one, at the source.

## Decision

This ADR owns the following fourteen generator declaration requirements:

1. A facade letter belongs to the module that declares it in its explicit `__all__`.
2. An `__init__.py` propagates; it never declares.
3. The root inherits from the main module; the root `__all__` overrides.
4. Internal tiers are detected from folders with Python; `src/` is public, the rest
   internal; no list anywhere.
5. Internal tiers inherit by class MRO and declare their own letter; a subdirectory
   declares no short alias.
6. The generator propagates, never compensates; the validator reports.
7. Violations are fixed at the source; recurrence makes a catalog rule with a fixture.
8. Verdict and count derive from one classification and the current
   [phase-completion contract](../../../AGENTS.md#engineering-and-phase-completion-contract).
   The former blanket statement that warnings do not fail is superseded by that
   contract; a warning, missing execution or partial result never proves acceptance.
9. Every rule is computed from an existing source and proven fleet-wide before commit.
10. Declaration adjustment is automatic; deriving beats listing; unnecessary lists die.
11. Every module is one nested class; nothing loose, no alias outside `__all__`; the
    existing rules become `error`.
12. An exception is a single motivated entry authorized explicitly by the operator.
13. A hack's permission dies in the same commit as the hack.
14. Every module obeys every rule (FLEXT, SOLID, DRY, YAGNI, CA, SSOT, DI); strict
    compliance is the dedup mechanism expected to free 60–80% of the code.

### Nested facade projection

#### Template-backed native refactoring (operator clarification 2026-10-30)

Existing templates are the structural base for refactoring existing modules as
well as creating absent declarations. During `make mod`, the existing Infra Rope
infrastructure catalogs native declarations and assembles their semantic content into the
existing typed render context; templates fill their owned slots. Preserve
authored bodies, execution order, identities and source trivia through native
refactoring. This does not authorize another parser, parallel renderer, relocated
monolith or manual generated-file repair. Reuse validated models and protocols
by reference, with defaults for optional inputs and explicit required inputs.

Candidate parse failure must preserve the original cause at the existing typed
failure boundary. It must never select physical bytes in place of candidate
bytes, parse a replacement module or inject that replacement into the native
module cache. Repair the operation that produced the invalid candidate.

The 2026-11-01 projection correction below confines this semantic refactoring
contract to `make mod`; `make gen` consumes declarations without changing authored
structure. Preserve existing class/member shapes, bodies and public functionality.
Compose the existing typed owners through CA and explicit DI to reduce coupling
and the execution chain; do not replace it with wrappers or another engine.

This amendment states the accepted contract, not implementation acceptance.
The 2026-10-30 handoff
records source limits and failing runtime receipts; `flext-u9h2i` owns execution
and closure. Fix-forward adoption under the root `AGENTS.md` "Rig and Lane
Contract" remains mandatory; no clean or quiet workspace prerequisite applies to
this projection.

The generator applies [ADR-014's semantic ownership](014-family-part-shape-rope-codemod-rules.md#1-semantic-facade-ownership)
recursively: a direct family domain facade composes the declarations in its private
`_domain/` directory by MRO, and nested private directories repeat that pattern.
Each generated lazy `__init__.py` reflects only its immediate modules' explicit
`__all__`; a subdirectory declares no short alias and an ancestor never republishes
leaf implementations around their owner. A source move and the affected subfacade and
ancestor lazy exports are planned and published as one authenticated candidate, from
source without importing the stale package being repaired. Callers use the nearest
composed facade at every stage (ADR-028 [Decision 10](028-facade-boundary-orchestrators-declarative-enforcement.md#decision-10)).

Exported data classes retain their nominal identity. In particular, a subclass of a
native data type is a published member, not a namespace composition base; exporting
two such classes never combines their instance layouts in the facade's MRO.

**Projection-engine correction, approved 2026-11-01.** The incident mandate
supersedes the 2026-10-29 requirement to use native semantic machinery during
generation. `make gen` projects declarations through one typed, invocation-local
source inventory parsed with the standard-library AST. It opens no Rope projects,
moves no modules, rewrites no consumers and runs no semantic convergence loop.
Family composition and direct exports retain all declared module correspondence,
types and identities. Missing or ambiguous declarations fail explicitly; generated
initializers and existing generated filenames never become declaration authorities.
The second generation must produce identical bytes, and the canonical generation
budget is below 20 seconds. Semantic discovery, structural repair, consumer
rewiring and source movement remain owned by `make mod` and its native workspace.
This separation introduces no substitute semantic engine or alternate publisher.

The existing [engine guide](../../guides/engine.md) and
[Infra execution contract](https://github.com/flext-sh/flext-infra/blob/0.12.0-dev/docs/guides/execution-context.md#workspace-snapshot-and-analysis-engine)
apply this target. Acceptance re-exercises the original public failure, then
generation across FLEXT, AI Hub, OUD and their governed subprojects with their
selected physical environments. Preserve pilot order and coverage, runtime-first
proof, frozen analyzer policy, full native gates and integrated evidence; a
shorter source file or an isolated passing consumer does not prove completion.

Planning and runtime acceptance are different boundaries. Projection planning reads
authenticated declarations and explicit candidate bytes without executing the target
package. Semantic modification retains the native workspace and its candidate
overlays. Acceptance exercises the generated public
surface in a fresh process. A source move must not require its obsolete export
map to import successfully before the replacement can be planned.

The existing lazy-map freshness validator remains the owner of drift reporting.
Its source comparison is necessary but not independent proof of correct exports:
runtime acceptance must also resolve declared exports, their native identities
and consumed MRO capabilities. Static and lazy bindings account for declared
eager metadata without lifting child exports into ancestors. Missing targets,
colliding identities and invalid ownership fail explicitly.

#### Deferred heavy capabilities (amended 2026-11-05, 2026-11-12, 2026-11-13)

**Every facade part (amended 2026-11-13).** The operator answered "Adiar toda
parte de fachada" on 2026-11-13 (tracker memory
`operator-decision-2026-11-13-defer-every-facade-part`; bead `flext-2ayig`). It
replaces the declared-distribution criterion of 2026-11-05 (tracker memory
`operator-decision-2026-11-05-lazy-declared-distributions`), whose goal it keeps:
the xlsx and docx libraries, and every other part, load only on use
(`operator-ruling-2026-10-02-lazy-heavy-capabilities`). There is one rule and no
declaration.

- Evidence (2026-11-13): only 9 flext-infra initializers carried deferred members
  and no other package had any, so the first read of `m` loaded the whole composed
  tree: about 2,400 modules and 8 s of process CPU for `ai-hub --help`.
- The lazy-init generator reads the same source inventory it already uses. It
  marks as deferred every class export that a family facade composes by MRO: a
  base, directly or through other in-package bases, of the package's facade root
  classes of the namespace families (`c`, `t`, `p`, `m`, `u`, derived from the
  core package as for every family fact), from the same source facts. The facade
  root classes stay real. Another facade, such as the service base `s`,
  composes model mixins that stay real: a stand-in cannot join a Pydantic
  metaclass. A stand-in is only valid for a namespace mixin, never for a class
  that is instantiated or subclasses a third-party type (amended 2026-11-12).
- **Shared member index (amended 2026-11-13).** The operator chose on
  2026-11-13 that the generator shares the index instead of copying it, with no
  gate change (bead `flext-2ayig.6`). A stand-in lists only the names bound in its
  own class body, excluding dunders. Its bases are the stand-ins of its
  in-package bases, in the real class's base order, each read from the
  initializer that exports it, so C3 linearization of the stand-ins reproduces
  the real MRO. An in-package base that no initializer defers has its members
  listed on the deriving stand-in; a name bound by both that base and a deferred
  base fails generation by name, because the flattened order could differ from
  the real MRO. Evidence: copying the inherited members of every composed part
  made generated initializers exceed the configured module size cap and repeat
  one another (ai-hub `_protocols/__init__.py` grew from 166 to 1,075 lines and
  `make check` reported 12 duplicated blocks between initializers); sharing
  removes about half of each index (ai-hub `_protocols` 828 to about 384 members).
  An initializer whose own index still exceeds the cap after sharing is split
  under a separate decision; the gate stays as it is.
- The generated initializer publishes those exports as deferred. `FlextLazy`
  hands consumers a stand-in class of `FlextLazyMember` descriptors. The first
  member access loads the declaring module through the lazy loader and caches the
  real member on the stand-in. Facades compose the stand-in by MRO, so importing
  a facade loads no part module.
- Type checkers read the real class through the initializer's `TYPE_CHECKING`
  imports. Consumers, facades and authored modules do not change.
- Generation fails explicitly for a facade-composed export with an
  out-of-package base, or one whose member set cannot be computed from source.
  Such a part is corrected at its source; it is never left eager. A protocols
  namespace that is itself a runtime-checkable `Protocol` is such a part: the
  rule `protocol-namespace-part-plain` makes it a plain class through `make mod`,
  as flext-core and flext-cli already declare it, and its nested contracts stay
  protocols.
- Acceptance: a fresh process imports every facade and loads no part module, and
  runtime acceptance resolves every deferred member through
  `resolve_lazy_members`. A broken target fails exactly as an eager import
  would. The proof of the cost is the real `--help` of each CLI.
- The `deferred_distributions` declaration is deleted with its planner branch.
- A package also declares, in the same section, its configuration roots whose
  validation is costly (operator choice 2026-11-13, "Lazy flext-infra settings").
  The initializer publishes each such root as a stand-in instance: importing it
  builds nothing, and the first attribute read loads the root's declaring module
  through the lazy loader, which runs its `fetch_global`, and forwards to the
  root. The stand-in keeps the root, never a member, so an in-place
  `reset_for_testing` stays visible. Validation errors of the root, such as a
  required setting with no source, surface unchanged on that first read. A
  declaring module that does not publish the root raises `ImportError` with its
  cause, never an `AttributeError` that would read as a missing name. Importing
  `c`, `t`, `p`, `m` or `u`, and the codegen preview that imports the package,
  then validates no configuration, as `FlextConfig` requires.
- Status (implemented): the repository declaration lists the roots as
  `deferred_instances` (for example `deferred_instances: [settings]`). There is
  no default; each package names its own roots. The lazy-init generator emits,
  right after `install_lazy_exports`,
  `defer_lazy_instances(__name__, globals(), {<root>: <module>}, (<root>,))` in
  every initializer of the project that exports a declared root, and generation
  fails when no initializer exports it. flext-core owns the runtime,
  `FlextLazyInstance` and `defer_lazy_instances`, which validates every name
  against the map it receives before any effect (flext-core#777,
  flext-infra#2356, bead `flext-14y32`).
- These two are the only deferral forms outside `__init__.py` and `flext.lazy`.
  Method-local imports, operation registries, module-object attribute access and
  `TYPE_CHECKING` class splits remain prohibited.

##### Structure of every facade letter (amended 2026-11-12)

The operator ruled on 2026-11-12, translated from Portuguese: "you have to fix
the whole c, t, p, m, u layer, otherwise it does not lazy load", and named the
flext-cli spreadsheet structure as the form to follow. A stand-in defers a
module only when nothing reads it while a facade is being composed, so each
letter has one structural rule. Measured on flext-infra with `libcst`,
`pytest`, `rope` and `gitpython` declared: before, `c` loaded libcst and
pytest, `t` and `m` added rope, and `u` added git; after, a fresh process
imports each of the five letters and loads none of them.

- **`c` and `t` — single-purpose holders.** Library classes and aliases stay
  named through the facades (ADR-028 point 2): `c.<Ns>.<Lib>.<Name>` for runtime
  operands and `t.<Ns>.<Lib>.<Name>` for annotations. Their holder is a class in
  a module that declares nothing else, and it is the only module of its family
  that imports the distribution. A holder never shares its class with a member
  that another module reads while its own class is created: that read loads the
  library for every importer of the facade.
- **`p` — structural only.** A protocol names library objects by shape. It
  imports no distribution at runtime.
- **`m` — no library type in a field.** Pydantic evaluates every field when the
  model class is created (ADR-028 Decision 14), so a field typed with a library
  class or with an alias of a deferred holder loads the library at import. A
  field carries an own enum whose values a contract test binds to the installed
  library, a protocol the library object satisfies, or `Hashable` when the
  object is only an identity key.
- **`u` — light boundary, private adapters.** The facade composes a boundary
  class whose methods delegate at call time. The modules that import the
  distribution are adapters in a private subpackage. A class that subclasses a
  library class is an adapter: it has no stand-in, stays a plain lazy export,
  and no facade composes it. A boundary reaches an adapter through its
  subpackage object at call time (`_xlsx.FlextCliUtilitiesXlsxRenderer`,
  `_rope.FlextInfraRopeProject`), never through a name bound at import.
- **Imports go through the package.** A runtime import of a deferred export
  names its package, never its declaring module: the module path bypasses the
  stand-in and loads the library.
- **Generator.** A PEP 695 `type` statement in a class body is a member. A base
  declared by an ancestor package resolves to its one declaring module. A class
  that binds no member is not deferred. A class with a base from a declared
  distribution is an adapter and is not deferred; any other unresolvable base
  still fails generation.
- **Acceptance.** For each of `c`, `t`, `p`, `m` and `u`, a fresh process
  imports the letter and holds no import package of a declared distribution in
  `sys.modules`; a deferred member read afterwards is the library's own object.

**Error-handling amendment, 2026-10-29.** Generation handles operational and
domain failures through the existing typed models/results and publisher at the
smallest coherent transaction or cohort. Diagnostics retain the original cause,
traceback and scope context. A local failure does not abort proven independent
units; an integrity failure stops its unsafe dependents. Account explicitly for
failed and unreached work, preserve confirmed effects and concurrent WIP, and
return nonzero when any error remains. There is no silent skip, catch-and-continue
success, broad capture that normalizes an unexpected exception, or parallel error
framework. This supersedes the former invocation-wide abort requirement, without
admitting dependent publication after a failed prerequisite.

Operational planning state, repository outcomes and candidate-plan coordination
use the existing mutable model preset and retain their typed collaborators by
reference. Expected domain outcomes select a typed branch before calling native
operations; they are not represented by deliberately raised exceptions. Immutable
file plans and authenticated source witnesses retain their existing protection.
Real dependency exceptions are contained once at the responsible boundary with
their causal evidence and failed outcome preserved. Existing aggregation retains
structured failures for affected units rather than only concatenating messages.
Typed owners supply legitimate defaults for optional inputs and require only
non-derivable mandatory values; no error-triggered default substitutes for evidence.
The bootstrap consolidation
contract belongs to
[ADR-014](014-family-part-shape-rope-codemod-rules.md#core-lazy-bootstrap);
`flext-s9r3a` and `flext-1engx.15` retain implementation ownership under the
`flext-brr3y` campaign.

#### Projector bootstrap dependency cut

The operator's 2026-10-29 decision is to decouple the existing projector while
preserving every contract. Its original planning models and the same projection
implementation must be available before importing the aggregate facades whose
exports they repair. Initial Make/CLI selection elects that same projector through
an acyclic public package boundary. Refactor the original declarations and their
consumers as one dependency group; retain one model, projector, renderer and publisher.

This is not an exception to
[ADR-028 Decision 10](028-facade-boundary-orchestrators-declarative-enforcement.md#decision-10).
Imports remain static through public package exports; no defining-module bypass,
method-local import, mirrored DTO, compatibility alias, second CLI or hand-written
initializer may bridge the cycle. Preserve model validation, wire contracts,
ownership, source receipts and failure semantics. Qualification exercises the
original cold Make entrypoint and its consumers; source decoupling alone proves
neither generation nor installed runtime recovery.

### Model and service protocol projection

**Amendment 2026-10-28 — accepted operator target, implementation and runtime
acceptance pending.** `flext-vjj1s.8` owns the existing model-to-`p` restoration;
the operator's newer instruction extends that owner to first-party service
contracts, source-module layout, automatic consumer rewiring and pilot coverage.
The MRO/Pydantic analyzer and environment acceptance tracked by
`flext-itpd1.13.11` remains incomplete and is not replaced by this amendment.

**Operator amendment 2026-11-02 — strict protocol typing.** Every `m.*` type
reference is prohibited. First-party model, service and data contracts are typed
through their canonical `p.*` protocols, each decorated with `@runtime_checkable`.
This includes callback signatures, aliases, quoted references,
generic arguments and service payload specializations; runtime evaluation of a
typing expression does not make a concrete-model annotation permissible.
Earlier exceptions retaining `m.*` annotations are superseded. Class-body
model fields are the one position excluded, as superseded by the 2026-11-09
amendment below.

Executable construction, validation, serializers, schema and handler metadata
retain the actual model owner: a Protocol is never instantiated. A value-level
constructor/schema reference is distinct from a type annotation. Preserve the
existing canonical scalar, enum and external SDK type owners; this decision does
not authorize SDK-shaped protocol mirrors or aliases that disguise model classes
as protocols.
Native model base expressions and metadata factory calls such as `m.Field`
remain actual model construction. They do not permit `m.*` in a type operand;
the native migration distinguishes these roles by syntax and resolved identity.

Use the existing `t.Port[p.X]` only for a genuine validated DI capability under
ADR-019. Its dependency exclusion from serialization and JSON Schema cannot
replace a persisted payload's validation. Persisted model fields name their
concrete model directly, which preserves its native validation, serializers
and schema (superseded for fields by the 2026-11-09 amendment below). Metadata
expressions that construct or validate a model are runtime expressions, not
annotation targets for the reception codemod.

**Amendment 2026-11-09 — simplified model fields.** Model fields now use the
model directly (``m.<Model>``) instead of the deferred schema owner form
``Annotated[<protocol route>, t.schema_for_model(lambda: <model>)]``. The protocol
mirror and deferred schema owner are no longer needed at the field boundary; the
model itself owns validation, serialization and JSON Schema. Qualify that
contract with real ingress, serialization and consumer execution; do not invent a
compatibility schema, suppress a failure, or restore a prohibited form to obtain
green.

The existing generator and native Rope modification owner complete this cutover
coherently across the declared inventory. Required protocol declarations,
dependent initializers and facade exports precede consumer use in the same
authenticated candidate. Blind prefix replacement is not semantic migration.
An unresolved declaration or unsupported native schema contract fails before
publication and is repaired at its owner. Source changes alone do not establish
runtime, gate or integration acceptance.

Every `make gen` derives model and service structural protocols through the
existing flext-infra projection owner. Its input is the complete authenticated
AST source inventory of the elected repository/workspace, including `src`,
`tests`, `examples`, `scripts` and every other discovered Python module. These
examples are not a closed tier list. Projection follows declared source identities,
inheritance, nested facade ownership and specialization;
neither filename spelling nor an existing consumer reference limits coverage.
Every discovered model and service receives an accounted classification and
projection disposition. Unresolved identities fail with their original cause;
they are not omitted or normalized into an empty successful projection.

The output describes the first-party declaration's actual structural contract.
Model protocols preserve effective field and computed-property types,
inheritance, generic specialization and read/write capability. Service protocols
preserve their own public callable contracts, including sync/async behavior,
parameter kinds, defaults in signatures, overloads, generics and return types.
This does not copy an external SDK into a local typing surface. Existing authored
DI ports remain their declared capability owners; generation neither replaces
A frozen model's protocol cannot inherit writable fields from a mutable model's
protocol. Its projection declares those inherited fields as read-only members;
the model's native inheritance and runtime behavior remain authoritative.
them with a service implementation nor weakens an originating contract.
Constructors, validation, field defaults/factories, schema, model configuration,
validators, serializers and handler metadata retain their real runtime owners.
A structural projection never becomes a second runtime model, validation engine
or operation/schema registry.

The newer operator enum decision in ADR-005 and ADR-028 Decision 14 distinguishes
input validation from outward serialization: governed model presets use
`use_enum_values=False`, superseding the intermediate primitive-output decision.
A complete `StrEnum` remains the input and stored field type, and the projected
getter and mutable setter retain that enum. Frozen fields have no setter.
Default and factory producers, strict Python construction, JSON validation and
existing enum consumers must close in the same migration. Python dumps retain
members; JSON serialization emits values at the actual outward boundary.
Retaining source text alone is not proof of preserved behavior. Proper subsets
and discriminators keep their narrower law.
Model contracts mirror `_models/` beneath `_protocols/`. Internal service
contracts and authored DI ports live beneath `_protocols/_services/`; external
integration capabilities live beneath `_protocols/_external/`, named by capability
and domain. Each module owns one holder with nested contracts. Service projections
remain source-derived; authored ports remain consumer-owned. External contracts
describe only consumed capabilities and reuse official types rather than mirroring
SDKs. Native declaration identities and consumers determine placement, not filename
heuristics. Facades and initializers compose these holders without changing public
`p` identities. `make mod` owns moves and complete consumer rewiring.

The existing census and modification pipeline executes ordered phases:
classify native declarations and destinations, relocate owners, rewire the complete
consumer closure, then project and validate the coherent candidate. Phase outputs
share the authenticated native source view and refresh affected inputs; generation
does not discover a repair by repeatedly attempting publication.
The census and portable intent must cover Python bindings of every kind, including
modules, classes, functions, methods, fields, variables, constants and aliases.
Their native scopes and dependencies must retain properties, descriptors, closures
and implicit consumers in the same relocation cohort. Identify existing model
protocols by their actual public bindings; record the planned destination of an
absent projection without requiring it to exist. Missing or ambiguous source
bindings fail explicitly rather than disappearing from the census.

### Single-read, single-batch publication (amended 2026-10-28, campaign `flext-pipol`)

Read-only planning inputs travel separately from effects in each
`CodegenFilePlan.inputs`, retaining their original atomic observations by
reference. The existing publisher verifies those observations under the same
native file-change lock used for effects before any publication. A YAML or
dependency manifest consumed only as input never acquires invented destination
ownership. This transport is an implementation requirement, not a claim of
completed concurrency or fix-forward recovery validation.

**Amendment 2026-10-28 — accepted contract, implementation pending.** The

**Implementation 2026-11-13 — writer barrier for generation (flext-jg6y2,
flext-infra#2405).** `codegen generate` holds the existing mutation barrier
(the reentrant file-change lock on the repository's mutation lock path) from

generation waits. The lockless plan-and-reconcile path and its

**Recovery supersession 2026-10-29 — operator order (`ag-ssut`, related
`aihub-6sls5.2`).** The 2026-10-28 permission for transaction-owned rollback is
historical and no longer operative. The canonical atomic-effects governance rule
owns preservation of published effects and correction forward. The small-transaction,
reader-barrier, authentication, scope and deadline contracts remain in force.

Within one repository invocation, an unchanged source observation is read and
parsed once. One native workspace model per repository (ADR-028
[Decision 17](028-facade-boundary-orchestrators-declarative-enforcement.md#decision-17))
feeds generation, lazy planning, model→protocol and docs. Changed observations
refresh incrementally in that same engine, invalidating only affected native
resources and dependent snapshot facts; no phase rebuilds the repository model
or repeats unchanged discovery. Each small transaction contains a complete
dependency closure, including moved sources, consumers, facades and lazy exports.
Its candidate is staged beside the existing mutation lock on the destination
filesystem, outside the working tree, and validated before live publication.

The existing publication owner extends its common mutation barrier to
cooperating Make and Rope readers. A reader enters before bootstrap imports,
configuration reads, discovery or any other live observation of the affected
scope. It retains protection for every later lazy read, or consumes a pinned,
independent candidate that requires no further live reads. A writer holds the
same barrier through source verification, file effects, Git-index retirement,
modes, directory creation/prune, incremental cache/model refresh, bounded
validation and durable completion. Multiple scope locks are acquired in one
canonical physical-root order, never with an inverted nested acquisition.
Subprocess validators consume the staged candidate and must not reacquire a
barrier their parent holds.

This guarantees atomic visibility of each transaction to those cooperating
readers, not an operating-system atomic replacement of several paths. An
uncooperative editor or raw reader is outside that visibility guarantee; its
changes remain protected by identity checks. Waiting for the barrier consumes
the same public Make deadline; it never creates an extra timeout budget.

Before the first effect, the publisher durably records the transaction identity,
scope, original observations and owned intended effects in its operational
record. It records completion only after validation and model refresh. Every
cooperating reader inspects that record while holding the barrier. An
interrupted or inconsistent transaction rejects live reads even when process
death has released the lock. Recovery reconciles that same record and its
authenticated effects before admitting readers; it never treats an absent
process or an expired lock as successful publication. The record belongs to
the publisher, not a substitute Beads tracker, semantic index or global cache.

On failure, preserve the first cause and every confirmed published effect,
including this transaction's index entries, file modes and directory effects.
Retain authenticated before/after observations and partial-effect evidence in
the existing operational record; they do not authorize restoration. Reconcile
drift and correct the canonical owner forward under the same source/target
authentication, compare-and-swap admission and cooperative barrier. Preserve
conflicting external edits and earlier transactions. Cleanup discards only
this invocation's unpublished staging and releases its own locks; its failures
remain attached to the primary failure. The operational record stays unresolved
until recovery is proved, the containing operation remains failed, and unreached
work is not successful.

The entire incremental transaction takes at most five seconds, including staged
validation, publication, native refresh and bounded failure recording/cleanup.
The existing performance policy owner declares that budget; the whole Make invocation,
including lock waits, staging and recovery, remains within sixty seconds.
Transaction sizing must leave failure-recording and cleanup margin inside these
limits. Fast validation never weakens the frozen analyzer rules or replaces the complete
gates and real consumer proof required for the slice. Exhausting either budget remains a
failure. Superseded planning/publication routes are removed in the same cutover.
