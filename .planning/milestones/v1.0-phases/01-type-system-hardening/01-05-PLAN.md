**Part A: TypeGuard -> TypeIs migration (TYPE-07)**

The 12 TypeGuard functions are in `flext-core/src/flext_core/_utilities/guards.py`. PEP 742 `TypeIs` provides bidirectional narrowing (narrows in both True and False branches), which is strictly better than TypeGuard for these use cases.

1. Read `guards.py` and identify all functions with `-> TypeGuard[...]` return type.
   Expected functions (from RESEARCH.md): `is_primitive`, `is_scalar`, `is_container`, `is_list`, `is_mapping`, `is_dict_like`, `is_list_like`, `is_flexible_value`, `is_pydantic_model`, `is_logger`, and 2 others.

2. For each function:
   - Change `from typing import TypeGuard` to `from typing import TypeIs`
   - Change return type from `TypeGuard[X]` to `TypeIs[X]`
   - The function body remains identical (isinstance checks).

   Example:
   ```python
   # BEFORE
   from typing import TypeGuard


   def is_str(value: object) -> TypeGuard[str]:
       return isinstance(value, str)


   # AFTER
   from typing import TypeIs


   def is_str(value: object) -> TypeIs[str]:
       return isinstance(value, str)
   ```

3. Search for any other `TypeGuard` usage across the entire repo:
   ```
   sg --pattern 'TypeGuard' --lang python
   ```
   Migrate any remaining TypeGuard references. No new TypeGuard should exist.

4. Update any re-exports in typings.py or **init**.py that reference TypeGuard.

5. Run `make gen` if facade exports changed.

6. Run `make pyre` and `make check PROJECT=flext-core CHECK_GATES=pyright` — both must exit 0. TypeIs is a drop-in for TypeGuard in these use cases, so no downstream breakage expected.

**Part B: Empty container literal annotation (TYPE-08)**

Pyrefly flags `implicit-any` for empty container literals like `x = []`, `y = {}`, `z = set()` without type annotations.

1. Run `make pyre` and filter for `implicit-any` or empty container warnings.
   Alternatively: `sg --pattern '$X = []' --lang python` and `sg --pattern '$X = {}' --lang python` across all projects.

2. For each empty container literal at an assignment site:
   ```python
   # BEFORE (implicit Any)
   results = []
   cache = {}
   seen = set()

   # AFTER (explicit annotation)
   results: list[str] = []  # use most specific type from context
   cache: dict[str, int] = {}
   seen: set[str] = set()
   ```

3. Determine the correct type annotation by:
   - Looking at what gets appended/added to the container in subsequent code
   - Looking at the function return type or the variable's usage context
   - Using `t.*` contracts where appropriate (e.g., `list[t.Scalar]`)

4. Scan ALL projects (not just flext-core) — empty container literals can exist anywhere.

5. IMPORTANT: Only annotate at assignment sites (not in function calls or comprehensions — those are not `implicit-any` violations).
