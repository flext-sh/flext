## Architecture Patterns

### Pattern: Exception Specificity

For each bare `except Exception:`, determine the specific exception from the try-block operations:

| Operation | Specific Exception |
|-----------|-------------------|
| File I/O | `OSError` |
| JSON parse | `json.JSONDecodeError` |
| Dict/list access | `KeyError`, `IndexError` |
| Import | `ImportError` |
| Type conversion | `ValueError`, `TypeError` |
| Docker operations | `docker.errors.DockerException` |
| Oracle DB | `oracledb.Error` |
| LDAP | `ldap3.core.exceptions.LDAPException` |
| Pydantic validation | `pydantic.ValidationError` |
| Generic runtime | `RuntimeError` |
| Multiple possible | `(SpecificA, SpecificB)` tuple |

### Pattern: print() to FlextLogger

```python
# Before
print(message)  # CLI output

# After — use structlog
logger = structlog.get_logger(__name__)
logger.info(message)
```

For `scheduled_maintenance.py` specifically — this is an echo command handler that simulates shell `echo`. Using `logger.info(message)` preserves the behavior while using the proper logging abstraction.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Logging | `print()` | `structlog.get_logger()` or `FlextLogger` | Structured output, log levels, correlation |

## Common Pitfalls

### Pitfall 1: Over-specifying exceptions in test cleanup

**What goes wrong:** Making test teardown too specific causes resource leaks when unexpected errors occur
**How to avoid:** D-03 exempts test helper utilities (conftest_factory.py, docker_infra.py) that genuinely need catch-all

### Pitfall 2: Confusing method calls with bare print()

**What goes wrong:** Replacing `console.print()` or `cli_api.print()` — these are Rich/CLI methods, not bare `print()`
**How to avoid:** Only target `print(` at statement level, not `.print(` method calls

### Pitfall 3: Docstring false positives

**What goes wrong:** Grep finds `print()` inside docstring examples (prefixed with `...`)
**How to avoid:** Already filtered in this research — only `scheduled_maintenance.py:590` and docs copy are real
